# 5 分钟演示脚本

> 目标：让面试官看到“业务闭环 + 工程化 + 评测”，而不是只看聊天。  
> 建议用离线模式演示，稳定、零成本；最后说明 DeepSeek 在线也能跑。

## 0:00–0:40 开场

```bash
cd xiaomei-shop-agent
python run_api.py --port 8000 --offline
```

打开 `http://127.0.0.1:8000`。

> “这是一个电商全品类生活馆 Agent，覆盖客服、售后、导购、选品和营销。它不是纯聊天，所有商品、订单、库存、售后都走工具；今天重点看四个东西：工具、RAG、情绪补救、评测。”

## 0:40–1:40 全品类 + 分人群

输入：

```text
你们卖什么
```

预期：`list_categories`，7 个部门。

输入：

```text
给老人买一双防滑鞋，预算300以内
```

预期：`search_products`，老人防滑健步鞋，259 元，宽楦/防滑，追问尺码。

> “它不是默认卖美妆。先判断部门、给谁买、预算，再决定问尺码、年龄还是过敏原。”

## 1:40–2:20 儿童安全边界

```text
给5岁孩子买点零食，要安全一点
```

预期：儿童奶酪棒/每日坚果；提到乳制品/坚果过敏、5 岁呛咳风险。

> “儿童场景先问年龄和过敏，不推荐成人药品，食品安全边界写进 Prompt 和工具数据。”

## 2:20–3:00 美妆 RAG + 对比

```text
我是油皮，想买300以内的面霜
清润控油面霜和修护保湿面霜哪个好
```

预期：推荐清润；对比价格/人群/成分/库存；带风险提示。

> “FAQ 走 RAG，25 条检索评测 Hit@1 100%；商品事实走工具，不靠模型记忆。”

## 3:00–3:50 订单/售后

```text
帮我查订单 DD2026001 到哪了
DD2026009 用了过敏，要退货
```

预期：顺丰单号/轨迹；退货申请 R 开头，退款金额，1-3 个工作日。

> “订单校验归属，退货校验签收时间/拆封/原因；质量问题走特殊通道。真实项目把 JSON 换成 ERP/OMS API，我已经留了 HTTP 客户端和 mock ERP。”

## 3:50–4:30 情绪补救

```text
你啥态度
```

预期：先道歉、复述、给选项；不转人工、不辩解。

```text
我要投诉
```

预期：建工单，`[转人工]`。

> “情绪分级：态度不满先补救；投诉/12315 才转人工。输出层还会拦截‘不演了/你爱买不买’这类防御性话术。”

## 4:30–5:00 工程与评测

```bash
python -m pytest tests -q
python eval/run_eval.py
python eval/rag_eval.py
```

说：

> “55 个测试、48 条 Agent 评测、25 条 RAG 检索评测；工具命中 100%、转人工 100%、防御性话术 0。还有 Docker/CI/Locust 和 `/api/metrics`。这些数字是我自己跑出来的，不是写在 PPT 上的。”

## 收尾

> “下一步我会用 LangGraph 把 intent→retrieve→plan→tools→reflect→respond 做成显式图，再补 dense RAG 和真实 ERP 沙箱。这个项目现在能证明：我能把 Agent 从 demo 推到可评测、可部署、可讲清取舍的状态。”

## 演示注意事项

- 不要一上来讲模型参数；先讲业务问题。
- 不要念功能列表；每讲一个功能，立刻演示。
- 不要回避失败：主动说“48/48 是自建集，真实用户不一定 100%”。
- 如果网络/API 不稳定，直接用 `--offline`，并说明“线上模式已接 DeepSeek，离线是稳定演示路径”。
