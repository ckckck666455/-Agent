# 数据与隐私说明

## 1. 这个仓库里有什么数据

- `data/products.json`：35 个虚构商品。
- `data/orders.json`：12 个虚构订单。
- `data/users.json`：7 个虚构用户，手机号已脱敏。
- `data/faqs.json`：25 条虚构店铺政策。
- `data/promotions.json`：5 个虚构活动。
- `eval/`、`loadtest/`：本地评测/压测产物，不含真实用户。

**没有真实客户、真实订单、真实支付、真实地址。**

## 2. API Key 怎么处理

- `.env` 只存在本地，已在 `.gitignore` / `.dockerignore` 中排除。
- 仓库里只有 `.env.example`，Key 为空。
- 日志/评测报告不打印 Key。
- 生产环境应使用密钥管理服务，不要用 `.env` 明文。

## 3. 用户身份

演示版 `user_id` 由客户端传入，仅用于演示。  
生产必须：

- 从登录态/网关注入 `user_id`，禁止客户端伪造。
- 会话表校验 `session_id` 归属。
- 订单接口做归属校验。
- 敏感操作加二次验证/审批。

## 4. 日志与审计

- SQLite 审计表记录事件类型、用户/会话、脱敏后的文本。
- 手机号/邮箱/身份证在写入日志前脱敏。
- 生产要设置保留期、访问控制、加密与删除机制。

## 5. 删除数据

演示环境直接删除 `runtime/shop_agent.db` 即可重置。  
生产需要提供用户数据导出/删除接口，并遵守当地隐私法规。

## 6. 如果你要换成真实数据

1. 先脱敏，再入库。
2. 不要提交真实订单/聊天记录到 Git。
3. 评测集单独存放，访问受控。
4. 对外截图前检查手机号、地址、订单号、姓名。
